35  Making a Workbook Someone Else Can Read

A workbook is finished when another person can open it, find the inputs, understand the calculations and avoid breaking the formulas. Correct arithmetic is necessary; a usable handoff is the rest of the job.

Learning Objectives

By the end of this chapter you should be able to:

  1. Match a workbook’s structure and polish to its audience.
  2. Separate raw data, cleaning, analysis and presentation across sheets.
  3. Use labels, shading, borders and frozen panes to make a sheet readable.
  4. Build a README sheet with useful navigation and source information.
  5. Protect formulas while leaving intended input cells editable.

35.1 Start With the Audience

A workbook is one Excel file. It contains one or more worksheets, also called sheets or tabs. The audience determines how those sheets should be organized.

  • Only you: A temporary scratch file can use short labels and minimal formatting. Keep in mind that a file made for one calculation often becomes the file someone asks to see later.
  • Colleagues: Use clear sheet names, a short README, consistent labels and enough formatting to make the workflow understandable without an accompanying email.
  • Clients, regulators or the public: Present a polished interface, identify sources and update dates, distinguish inputs from formulas and keep working sheets away from the main results.

Polish should solve a reading problem. It is not decoration added after the analysis.

35.2 Give Each Sheet One Job

Complex workbooks are easier to inspect when raw data, cleaning, analysis and presentation occupy different sheets.

A useful structure is:

  1. README: purpose, author, update date, sources and a short description of each sheet.
  2. Raw data: the original import, left unchanged.
  3. Cleaned data: standardized names, corrected units and documented exclusions.
  4. Analysis: summaries and formulas used to answer the question.
  5. Output: charts or a compact table meant for the reader.

The exact number of sheets depends on the job. The principle is separation of concerns: a reader should know whether a value was imported, cleaned, calculated or prepared for presentation.

For example, a yield-summary workbook might use the following map on its README sheet:

Sheet Job Reader action
README Explain the file, sources and update date Start here
Raw_yields Preserve the imported records Do not edit
Cleaned_yields Standardize crop names and units Check documented changes
Analysis Calculate regional summaries Review formulas
Output Present the final table and chart Read or export

Keep a machine-readable table at A1 on its data sheet, with one header row and one observation per row. Put titles, instructions and decorative spacing on the README or Output sheet instead of above data that may later be imported into R.

35.4 Sympathy for the Reader

The author knows why a sheet exists, which cells are safe to edit and where a number came from. The reader does not.

Before handing over a workbook, ask:

  • Who will open it, and what do they already know?
  • What decision are they trying to make?
  • Will they read, enter values, refresh data or carry out a new analysis?
  • How much time will they spend finding the answer?
  • What mistake are they most likely to make?

Then open the file as though it arrived without an explanation. Start on the first sheet and see whether the next action is obvious.

35.5 Formatting for Handoff

The following habits make a workbook easier to use and audit.

Structure

  • Begin with a README. State the purpose, author, update date, sources and contents.
  • Use descriptive sheet names. Summary and Raw_yields are more useful than Sheet1 and Sheet2.
  • Keep raw data unchanged. Put corrections and calculations elsewhere so every result can be traced back.
  • Label every input and output. Include units in headers and chart axes.
  • Document assumptions. Put rates, prices and other inputs in labelled cells rather than burying them inside formulas.

Appearance

  • Use one visual system. Give headers, inputs, formulas and warnings consistent styles across sheets.
  • Freeze the header row. Long tables should retain their column names while scrolling.
  • Use number formats deliberately. Show dollars, percentages, dates and decimal places appropriate to the measurement.
  • Use conditional formatting for exceptions. Highlight something that needs attention, not every cell that contains a value.

Colour should carry meaning. If green cells are inputs on one sheet, do not use the same green for calculated outputs on another.

35.6 Hyperlinks

A README can link readers to the sheets and sources they need. Select a cell and use Insert > Link or press Ctrl+K on Windows or Cmd+K on macOS.

Three destinations are common:

  • A place in this workbook: choose a sheet and cell such as Summary!A1.
  • A file or web page: link to the agency page or file that supplied the data.
  • An email address: identify the person responsible for questions or updates.

The formula form is useful when the link text or destination is generated:

=HYPERLINK("#'Raw yields'!A1", "Raw yields")
=HYPERLINK("https://saskatchewan.ca", "Data source")

The # identifies a destination inside the workbook. Single quotes are required around a sheet name that contains a space.

Links between sheets work reliably in desktop Excel but may not work in an embedded or read-only web preview. Keep tab names clear and mention the destination sheet in the surrounding text so the hyperlink is not the only route.

35.7 Locking Cells

A workbook with editable assumptions should protect its formulas from accidental typing. Excel uses a cell’s Locked property together with sheet protection.

Every cell is marked Locked by default, but that setting has no effect until the sheet is protected. The workflow is:

  1. Select the intended input cells.
  2. Open Format Cells by right-clicking the selection, or press Ctrl+1 on Windows or Cmd+1 on macOS.
  3. On the Protection tab, clear Locked, then select OK.
  4. Choose Review > Protect Sheet. Leave Select unlocked cells enabled. If readers need to sort or filter a protected table, also enable Sort and Use AutoFilter.
  5. Test an input cell and a formula cell before handing over the file.

The unlocked inputs remain editable; the other cells refuse changes. A password is optional. For most teaching and workplace files, protection is meant to prevent accidents rather than keep information secret.

To change the design later, choose Review > Unprotect Sheet, make the changes and protect the sheet again. If you used a password, Excel will ask for it.

Protection applies to each sheet separately and is not a security system. Treat it as a guard rail around formulas, not as access control for confidential data.
