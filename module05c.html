15  Graphing with AI

Graphing is a good place to begin using AI assistance. ggplot2 is consistent, but details such as annotations, direct labels and axis breaks require arguments that are easy to forget. An assistant can draft that syntax quickly.

Charts also expose many mistakes. A label beside the wrong year, a missing panel or a clipped axis can be seen. That makes the draft easier to check than a join that drops rows and still returns a plausible number.

Learning Objectives

By the end of this chapter you should be able to:

  1. Ask an AI assistant for ggplot2 code using the actual structure of a dataset.
  2. Check the data supplied to an AI-produced chart.
  3. Check the marks, labels, groups and scales drawn by the chart.
  4. Recognize when repeated prompting is no longer improving the result.

15.1 A Chart Does Not Check Its Data

A chart can show whether the drawing is wrong. It cannot show whether the wrong rows were supplied to it.

A clean chart of 2024 is still wrong when the question asked about 2025. Code that removes every row with missing acreage may also create a convincing figure while changing the population being described.

Check both sides of the plot:

  1. Before plotting, inspect the number of rows, groups, missing values and numerical ranges.
  2. After plotting, inspect the marks, labels, axes and panels.

The exercise data makes the distinction clear. sask_variety_yields.csv has 13,625 rows, including 4,186 with no recorded yield. The missing values are not spread evenly across years.

About half the 2021 rows have no yield, while almost all 2025 rows have one. A chart of 2021 therefore rests on a much thinner set of observations. Nothing in the finished chart reveals that unless the missingness is checked separately.

15.2 The Exercises

All five exercises use sask_variety_yields.csv. Its columns are Risk_Zone, Crop, Variety, Year, Acres and Yield.

Work in Positron with an assistant connected. For each exercise, describe the result, read the proposed code, run it and complete the checks. When the draft is wrong, tell the assistant what is wrong rather than asking it to produce the same chart again.

1. Annotate one point

Plot average spring wheat yield by year. Add a note with an arrow pointing to 2021 and identify it as a drought year.

Checks: Does the arrow point to 2021? Is the note inside the plotting area? Did the calculation average over the intended varieties? How many recorded yields contribute to each annual point?

2. Replace a legend with direct labels

Plot average yield by year for four crops. Put each crop name beside the right end of its line and remove the legend.

Checks: Are all four labels present and beside the correct line? Has a label been clipped at the panel edge? Can the series still be distinguished when printed in grey?

3. Shade a range behind a line

Plot average spring wheat yield by year and add a shaded band showing the range across risk zones.

Checks: Does the band contain the mean line in every year? Do the axis limits include the whole band? How many risk zones contribute to each year’s range?

4. Build small multiples

Find the six crops with the greatest total acreage. Make one panel per crop showing average yield over time.

Checks: Are there exactly six panels? Are the year labels readable? Do the panels share a vertical scale? Decide whether a common scale for comparing levels or free scales for comparing shapes better answers the question.

5. Rebuild a chart from Module 4

Choose a figure from Section 10.2 and reproduce it using only the description in the text. Do not open R/chart_types.R until the new version is finished. Then compare the two scripts and figures.

Checks: Does each figure make the same comparison? Which design decisions differ? Is either version clearer at the size used in the book?

15.3 A Useful Prompt Structure

A graphing request should state four things:

  • the data frame and relevant columns;
  • the rows or groups to include;
  • the calculation required before plotting;
  • the chart form and the specific design change needed.

For example:

The data frame d has columns Crop, Year, Risk_Zone, Acres and Yield.
Keep spring wheat rows with recorded Yield. Calculate mean Yield by Year and
Risk_Zone, then plot one line per zone. Put each zone name at the right end of
its line and remove the legend. Show the summary table before the plot code.

Asking for the summary table is useful. It separates the calculation from the drawing and gives you something numerical to inspect.

15.4 When the Assistant Gets Stuck

An assistant may repeat the same failed fix after each error report. More repetitions usually reinforce the same approach.

Try one of these instead:

  • Change the description. Restate the desired result rather than repeating the symptom.
  • Ask for an explanation. Understanding the error may reveal a one-line correction.
  • Reduce the problem. Remove extra layers until the basic plot works, then add them back one at a time.
  • Start a fresh chat. A conversation built around a mistaken approach can keep returning to it.

When those fail, use the package documentation or a worked example. The assistant is one route to the syntax, not the authority on it.
