2  Going Further with Excel

The first chapter covered how a spreadsheet works. This one covers the functions that make Excel worth using on real data: calculations that apply to only part of a table, pulling values in from a second table, and summarizing a long table by category.

Learning Objectives

By the end of this chapter, you will be able to:

  • Calculate on part of a table with IF, COUNTIF, SUMIF and AVERAGEIF
  • Build a criterion from a value you have to calculate first
  • Pull a value in from a second table with XLOOKUP, and read the older VLOOKUP and INDEX/MATCH versions when you meet them
  • Sort and filter a table without corrupting it, and know why a filter does not change what a formula returns
  • Recognize wide and long data, and say which one a task needs
  • Summarize a table by category with a PivotTable

2.1 Conditional Functions

Everything so far has applied to a whole column. Just as often you want an answer about part of it – the average yield on the canola fields, the number of fields over 60 bushels. Excel handles this with a family of functions that take a condition alongside the range.

COUNTIF counts the rows that match, SUMIF adds them up, and AVERAGEIF averages them. Each takes the range to test, the condition to test for, and (for SUMIF and AVERAGEIF) the range holding the numbers you actually want. IF is the simpler cousin: it looks at one cell and returns one of two things.

The worksheet works through all of them on eight fields. Column E labels each field with IF, and the block underneath answers six questions about subsets. Column F and column C show the formulas.

The last row of that worksheet is the one worth studying. When the number you are comparing against has to be calculated – “how many fields beat the average?” – you cannot write ">AVERAGE(D5:D12)", because everything inside quotation marks is treated as literal text. Excel would go looking for a cell containing those characters. Instead you glue the > onto the calculated number with &:

=COUNTIF(D5:D12,">"&AVERAGE(D5:D12))

Two more that come up constantly. COUNT counts cells containing numbers; COUNTA counts any cell that is not empty, text included. And a blank cell is not a zero: AVERAGE, COUNT and MEDIAN skip blanks, which is nearly always what you want. If you fill the blanks with zeros first, those zeros become real measurements and drag the average down.

2.2 Lookup Functions

Data usually arrives split across tables. You have yields by field in one place and crop prices in another, and you need them together. Pulling a value from the second table into the first is a lookup.

XLOOKUP takes three things: the value to find, the column to search in, and the column to return from. The worksheet below has a price list off to the side in H4:I7, and column E looks up each field's crop to bring back its price.

Download this workbook · blank version to fill in yourself · Open online (File → Save a Copy to view formulas and edit)

Underneath, the same lookup is written three ways. XLOOKUP is the one to use. VLOOKUP is older and still everywhere, so you need to be able to read it, but it has two traps: it can only search the first column of its table, and its last argument defaults to approximate matching. Leave that argument off and Excel will happily return a wrong answer without complaint, so always pass FALSE. INDEX/MATCH was the workaround before XLOOKUP existed and turns up in older workbooks.

Sometimes one column is not enough to identify a row. If each row is one rural municipality in one year, then RM 1 appears many times over and looking up “RM 1” finds only whichever year happens to come first. You need to match on RM and year. The trick is to join them into a single key with a separator:

=XLOOKUP(1 & "|" & 2023, B2:B10650 & "|" & A2:A10650, E2:E10650)

The separator earns its keep. Without it, RM 1 in 2023 and RM 12 in 023 would both collapse to 12023.

2.3 Sorting and Filtering

Sorting and filtering are not formulas – they are things you do to the sheet itself, so this section is mostly pictures of where to click. The examples use the same eight fields as before.

Sorting reorders the rows. Click any cell in the column you want to sort by, then use Sort & Filter on the Home tab (or the Data tab, which has the same buttons):

Sorting by Acres, smallest to largest, gives this:

That last point is the one to be careful about. Excel moved whole rows because the cursor was sitting inside the table. If you instead select a single column and sort that, Excel reorders those cells and leaves every other column where it was, so each row ends up holding some other field's numbers. Nothing warns you. Click one cell inside the data and let Excel work out the extent of the table.

Filtering hides the rows you are not interested in. Turn it on from the same menu:

Clicking one of those arrows opens a panel listing every value in the column, all ticked:

Untick everything except Canola and the other rows disappear:

Those blue, non-consecutive row numbers are worth learning to notice. They are the only sign that you are looking at part of a table rather than all of it, and forgetting a filter is on is a common way to get a wrong answer. Nothing has been deleted – clearing the filter brings everything back. Ctrl+Shift+L on Windows or ⌘⇧F on a Mac toggles filters on and off.

WarningFilters hide rows from you, not from your formulas

This trips up almost everyone. If you filter a column to show only 2023 and then write =AVERAGE(E2:E10650), Excel still averages every row — including the hidden ones. Ordinary functions (AVERAGE, SUM, MEDIAN, STDEV.S, QUARTILE.INC, …) ignore the filter completely. You would get the 1990–2025 average, not the 2023 average, and never notice.

To compute a statistic on a subset, do one of these:

  • Copy the visible rows to a new sheet, then compute there (the recommended workflow for this course). After filtering, select the visible data, copy, and paste into a fresh sheet — only the visible rows come along — then run your formulas on that clean subset.
  • Or use a conditional function that does the filtering itself: AVERAGEIF, SUMIF, COUNTIF (covered above), which never rely on hidden rows.
  • Or use SUBTOTAL / AGGREGATE, which are the two functions that do respect filters (optional, more advanced).

Whenever a task says “for the 2023 data, compute …,” your first move should be to isolate that subset — do not just filter and point a formula at the whole column.

2.4 Wide vs. Long Data

The same numbers can be laid out in two ways, and which one you have decides what you can do with them. The workbook below has the two shapes on separate tabs, with a page at the front explaining the difference.

Download this workbook · Open online (File → Save a Copy to view formulas and edit)

In the wide table, the crop is the column heading – three crops, three columns. In the long table, the crop is a value sitting in its own column, and every yield is stacked into a single Yield column. Same data, different shape.

Wide is easy to read and convenient for column-at-a-time arithmetic: average the Canola column and you are done. Long is what you need when you want to summarize by the thing that is stacked. A PivotTable can only group by a field that lives in its own column, so if you want average yield by crop, the crop has to be a column of values rather than a set of headings.

Neither is wrong. Reshaping between them by hand in Excel is tedious, which is one of the arguments for moving to R – there it is a single function call in each direction (pivot_longer() and pivot_wider()). You will meet the formal version of this idea, called tidy data, in Chapter 6.

2.5 PivotTables

A PivotTable summarizes a long table by category – average yield by crop, total acres by year – without writing any formulas. You drag the field you want to group by into one box and the field you want summarized into another, and Excel builds the table. The name comes from being able to pivot it: put crops down the side and years across the top, then swap them, then add a third field, all by dragging.

The workbook below is where this earns its keep. Its Data tab holds every variety of six major crops for five years – around a thousand rows, more than anyone can read. Each row is a provincial total: the acres are summed across all 21 risk zones and the yield is an acreage-weighted average across them, so the rows are directly comparable. The three summary tabs show what a PivotTable makes of it.

Download this workbook · Open online (File → Save a Copy to view formulas and edit)

To build one yourself: click any cell inside the data, then Insert → PivotTable, and put the result on a new sheet. You get an empty table and a list of your column headings. Drag one into Rows, drag the number you care about into Values, and the summary appears. Drag a second category into Columns for a two-way table. Filters applies a condition to the whole thing.

One setting catches everyone. Excel sums whatever you put in Values, so dropping Yield in there gives you the total of every yield figure, which is a meaningless number. Click on the value and change Summarize Values By to Average. The summary tabs in the workbook are all built this way, so you can check your own against them.

Two other things worth knowing. Show Values As turns the numbers into percentages of a row, column or grand total. And double-clicking any cell in a PivotTable creates a new sheet holding the rows that produced that number – the quickest way to check a figure that looks wrong.

A caution before reading anything into a comparison: check that the categories share a unit. The six crops in this workbook are all measured in bushels per acre, so averaging across them is fair. Pulse crops like lentils and chickpeas are reported in pounds per acre in the same source data, and a PivotTable will happily average those together with bushels and hand you a number that means nothing.

2.6 Excel Efficiency: Tips and Tricks

Everything above is about what to compute. This short section is about doing it faster. None of it is required to get the right answer — but once your datasets are bigger than a single screen (and the real ones in this course have thousands of rows), moving around with the mouse becomes painfully slow. A handful of keyboard habits will make you dramatically quicker, and they are worth building early.

Moving Around a Worksheet

The mouse is fine for a small sheet. But scrolling to the bottom of a 10,000-row column by dragging is misery. The keyboard jumps you there instantly. The shortcuts differ slightly between a Mac and a PC — on a Mac you generally use the Command (⌘) key where Windows uses Ctrl — so both are given below.

Action Mac Windows
Jump to the edge of a block of data (top/bottom/left/right) ⌘ + arrow Ctrl + arrow
Jump and select everything along the way ⌘ + Shift + arrow Ctrl + Shift + arrow
Select the whole column of data from here down ⌘ + Shift + ↓ Ctrl + Shift + ↓
Go to cell A1 (the top-left) ⌘ + Fn + ← Ctrl + Home
Go to the last cell with data ⌘ + Fn + → Ctrl + End
Move one cell (any direction) arrow keys arrow keys
Move to the next cell after typing Enter (down) / Tab (right) Enter / Tab
Edit the cell you are on (without retyping) Ctrl + U or double-click F2

The workhorse is ⌘/Ctrl + arrow: it flies to the edge of the current block of data. Sitting at the top of a column of yields and want the bottom? ⌘+↓. Add Shift and it selects everything on the way — so ⌘+Shift+↓ grabs the entire column of numbers, which is exactly how you feed a range into =SUM(...) or =AVERAGE(...) without dragging. (Careful: ⌘+arrow stops at the first blank cell. If your column has a gap, it stops there — press again to continue past it. This is also a handy way to find accidental blanks in your data.)

A Few More Time-Savers

  • The fill handle. The small square at the bottom-right corner of a selected cell. Drag it to copy a formula down a column (references adjust as you learned in Relative and Absolute References), or double-click it to auto-fill down as far as the neighbouring column has data — no dragging.
  • AutoSum. Select a cell just below a column of numbers and press Alt+= (Windows) or ⌘+Shift+T (Mac); Excel guesses the range and writes the =SUM(...) for you. (If the shortcut does not fire on your version, the AutoSum button — the Σ on the Home tab — does the same thing.)
  • Undo / Redo. ⌘+Z / ⌘+Shift+Z (Mac), Ctrl+Z / Ctrl+Y (Windows). Undo is your safety net — experiment freely, then undo.
  • Freeze panes. View → Freeze Panes → Freeze Top Row keeps your header row visible while you scroll through thousands of rows, so you never lose track of which column is which.
  • Copy a value, not the formula. Copy a cell, then Paste Special → Values to paste the result rather than the formula — useful when you want to lock in a number so it stops recalculating.

You do not need any of these to get the right answer — but the keyboard is far faster than the mouse once data gets large. Learn ⌘/Ctrl + arrow first; it alone will save you hours over the term.
