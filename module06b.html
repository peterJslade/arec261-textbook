18  Working with Spatial Data in R

Chapter 17 treated spatial data as something to look at. This chapter makes it something to work with. The sf package handles vector data and the terra package handles rasters, and both give you objects that the Module 2 verbs mostly work on unchanged.

The two working files are the RM boundaries from Chapter 17 and a slice of the 2023 Annual Crop Inventory covering two RMs, aci_rm_slice_2023.tif.

18.1 Reading vector data

st_read() reads most vector formats – GeoJSON, GeoPackage, and shapefiles, which arrive as a folder of files that travel together.

# Load the package for vector spatial data
library(sf)

# Read the RM boundaries
rms <- st_read("data/sask_rms.geojson")

18.2 Points from coordinates

A table with longitude and latitude columns becomes spatial with st_as_sf(). The coords argument names the two columns, longitude first, and crs = 4326 states what the numbers mean.

# Four cities as a plain table
cities <- tibble(
  city = c("Saskatoon", "Regina", "Swift Current", "Yorkton"),
  lon  = c(-106.67, -104.61, -107.79, -102.46),
  lat  = c(52.13, 50.45, 50.28, 51.21)
)

# Turn the coordinate columns into point geometry
cities_sf <- st_as_sf(cities, coords = c("lon", "lat"), crs = 4326)

# Print the spatial version
cities_sf

18.3 Transforming coordinate systems

st_crs() reports what a layer’s coordinates mean, and st_transform() converts them. Transforming the RMs to UTM Zone 13 turns degrees into metres:

# The CRS the file arrived in
st_crs(rms)$Name

# Convert from degrees to UTM Zone 13 metres
rms_utm <- st_transform(rms, 32613)

# The bounding box before and after
st_bbox(rms)
st_bbox(rms_utm)
> # The CRS the file arrived in
> st_crs(rms)$Name
[1] "WGS 84"
> 
> # Convert from degrees to UTM Zone 13 metres
> rms_utm <- st_transform(rms, 32613)
> 
> # The bounding box before and after
> st_bbox(rms)
      xmin       ymin       xmax       ymax 
-110.00574   48.99886 -101.36201   54.65333 
> st_bbox(rms_utm)
     xmin      ymin      xmax      ymax 
 133976.7 5427372.1  766069.5 6067730.1

Same province, different numbers: the first box is in degrees, the second in metres. Measurement is the reason to care. With the coordinates in metres, st_area() gives a real area – here, the RM of Corman Park in square kilometres:

# Area of RM 344, Corman Park, in square kilometres
rms_utm |>
  filter(RMNO == "344") |>
  st_area() |>
  as.numeric() / 1e6      # drop the m^2 label, then scale
> # Area of RM 344, Corman Park, in square kilometres

18.4 Attaching a table to boundaries

The RM boundaries carry no yields, and the RM yield table carries no shapes. The RM number links them. Read the yield file and keep the 2023 canola column:

# Read the wide RM yield file
rm_yields <- read_csv("data/rm_yields_1990plus.csv", show_col_types = FALSE)

# One row per RM: 2023 canola
canola_2023 <- rm_yields |>
  filter(Year == 2023) |>
  select(RM, Canola)

# Join the yields onto the boundaries
rm_canola <- left_join(rms, canola_2023, by = c("RMNO" = "RM"))
> # Read the wide RM yield file
> rm_yields <- read_csv("data/rm_yields_1990plus.csv", show_col_types = FALSE)
> 
> # One row per RM: 2023 canola
> canola_2023 <- rm_yields |>
+   filter(Year == 2023) |>
+   select(RM, Canola)
> 
> # Join the yields onto the boundaries
> rm_canola <- left_join(rms, canola_2023, by = c("RMNO" = "RM"))
Error: Can't join `x$RMNO` with `y$RM` due to incompatible types.
ℹ `x$RMNO` is a <character>.
ℹ `y$RM` is a <double>.

The join refuses to run: RMNO came out of the boundary file as text and RM is a number. The fix is to make the types agree before joining, and then to check what the join produced:

# Make the key numeric, then join
rm_canola <- rms |>
  mutate(RMNO = as.numeric(RMNO)) |>
  left_join(canola_2023, by = c("RMNO" = "RM"))

# Same 296 rows as the boundaries
nrow(rm_canola)

# RMs with no reported canola in 2023
sum(is.na(rm_canola$Canola))
> # Make the key numeric, then join
> rm_canola <- rms |>
+   mutate(RMNO = as.numeric(RMNO)) |>
+   left_join(canola_2023, by = c("RMNO" = "RM"))
> 
> # Same 296 rows as the boundaries
> nrow(rm_canola)
[1] 296
> 
> # RMs with no reported canola in 2023
> sum(is.na(rm_canola$Canola))
[1] 7

A left join keeps every boundary, so the row count matching rms is the first check, and the count of missing yields is the second – those RMs reported no canola that year, and Chapter 19 has to decide how to colour them. Mapping this object is where that chapter starts.

18.5 Which polygon holds a point

A spatial join matches rows by location instead of by key. st_join() attaches to each point the attributes of the polygon it falls in:

# Which RM is each city in?
st_join(cities_sf, rms) |>
  select(city, RMNO, RMNM)

18.6 Reading raster data

The terra package does for rasters what sf does for vectors. rast() reads the file, and printing the object answers the Chapter 17 questions – how many cells, how big each one is, how much ground they cover, and in what CRS:

# Load the package for raster data
library(terra)

# Read the crop inventory slice
aci <- rast("data/aci_rm_slice_2023.tif")

# Size, resolution, extent and CRS in one printout
aci

The slice covers the RMs of Wood Creek and McCraney at 30 metres, and its CRS is already UTM Zone 13. Figure 18.2 puts the boundaries over the cells.

# Shrink for display: each 8-by-8 block of cells becomes one cell
aci_small <- aggregate(aci, fact = 8, fun = "modal")

# The class table pairs each value with a crop name and a colour
classes <- read_csv("data/aci_crop_classes.csv", show_col_types = FALSE)

# Raster to a data frame of cell centres and values
aci_df <- as.data.frame(aci_small, xy = TRUE) |>
  rename(value = 3) |>                     # the third column holds the class
  left_join(classes, by = "value")         # attach names and colours

# The named palette for the classes present
pal <- aci_df |>
  distinct(crop, colour) |>
  deframe()

# The two RM boundaries, in the raster's CRS
pair <- rms_utm |>
  filter(RMNO %in% c("281", "282"))

ggplot() +
  geom_raster(data = aci_df, aes(x, y, fill = crop)) +
  geom_sf(data = pair, fill = NA, colour = "black", linewidth = 0.5) +
  scale_fill_manual(values = pal) +
  theme_void() +
  # A compact legend leaves more room for the map
  theme(legend.key.size = unit(4, "mm"),
        legend.text = element_text(size = 8)) +
  labs(fill = NULL)

The overlay works because both layers are in the same CRS. Had the boundaries stayed in degrees, the outlines would land nowhere near the cells – the rule from Chapter 17, in raster form.

18.7 Cutting a raster with a polygon

crop() trims a raster to a polygon’s bounding box and mask() blanks the cells outside the polygon itself. Together they cut one RM out of the slice, and freq() counts what is in it:

# Wood Creek, in the raster CRS
wood_creek <- rms_utm |>
  filter(RMNO == "281")

# Trim to the bounding box, then blank the cells outside the RM
aci_wc <- crop(aci, vect(wood_creek)) |>
  mask(vect(wood_creek))

# Count the cells in each class and turn counts into shares
freq(aci_wc) |>
  left_join(classes, by = "value") |>       # attach the crop names
  mutate(share = count / sum(count)) |>     # share of the RM
  select(crop, count, share) |>
  arrange(desc(share)) |>
  head(6)

This is the aggregation direction from Chapter 17 in action: a million 30-metre cells collapse to a handful of numbers about one RM. Each 30-metre cell is about 0.22 acres, so multiplying a count by 0.22 gives the class’s area in acres.

18.8 Writing spatial data

st_write() saves a vector layer and writeRaster() saves a raster. For vector output use GeoPackage rather than shapefile – a shapefile truncates column names to ten characters and splits into several files.

# Save the joined boundaries-plus-yields layer
st_write(rm_canola, "output/rm_canola_2023.gpkg", delete_dsn = TRUE, quiet = TRUE)

# Save the masked raster
writeRaster(aci_wc, "output/aci_wood_creek_2023.tif", overwrite = TRUE)
> # Save the joined boundaries-plus-yields layer
> st_write(rm_canola, "output/rm_canola_2023.gpkg", delete_dsn = TRUE, quiet = TRUE)
> 
> # Save the masked raster
> writeRaster(aci_wc, "output/aci_wood_creek_2023.tif", overwrite = TRUE)

The saved GeoPackage is what Chapter 19 reads back to make its first map.
